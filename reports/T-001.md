### Decisions I made
1. **Colour wheel in vs AI counts as a rematch in new colours**, so the first mover alternates there too. The task only defines New Game (human first) and Rematch (alternate).
2. **The AI's "current colour" before anyone has picked is the default O colour on first load (Pink).** So a human picking Lime keeps the AI Pink; a human picking Pink moves the AI to Sky blue.
3. **Colours are shared across modes.** After colours are picked in one mode, New Game into the other mode goes straight to the board with the same colours (X = the human in vs AI). The colour wheel changes them. This follows "colour picker if colours haven't been chosen yet this session".
4. When the AI moves first, the status says "AI is thinking…" from the start. It waits for the board's entrance (1.15 s), then its usual 400–700 ms.
5. During the AI's turn all cells are disabled rather than silently ignoring taps, so hover and press effects don't suggest you can play.
6. Pre-highlight is a white ring, like the selected colour swatch. The Mode step remembers the tapped mode even if the player goes ‹ Back without picking a difficulty.
7. **AC-15 fix (it was already failing before this task).** On screens ≤ 440 px the card's side padding is 16 px and the card clips sideways overflow. The picker's slide-in from 70 px to the right made Chrome's mobile emulation widen the page to 391–414 px. `overflow-x: hidden` on `html` did not stop that; clipping on the card did. Side effect: on phones the first-load card is narrower than before. Desktop is unchanged.
8. In the end-of-game row, Rematch and New Game have 20 px side padding (was 28), so all three controls fit within the board's width and the card doesn't widen when the row rises. The first-load New Game button is unchanged.
9. Confirm and the new step buttons ignore taps while the card slides. Side effect: a double-clicked Confirm no longer launches the board twice, which it could before.
10. On an empty board all nine moves score the same for Hard (draw), so its opening move can be any cell, edges included. That follows from "break ties randomly", and it still never loses.
11. Git had no author identity on this machine, so I committed as `Claude <noreply@anthropic.com>` (matching the existing history) per command, without changing any git config.

### Known issues / risks
- Safari (desktop and iOS) and real touch devices are untested. `overflow-x: clip` needs Safari 16+; older Safari ignores it and would show the sideways page widening that existed before.
- If the human moves within the first ~0.4 s of a new board, the AI's reply can land in a cell that is still popping in. That cell then pops in with the mark already inside. Cosmetic.
- The existing end-of-game timers (confetti 300 ms, action row 1100 / 250 ms) are still plain `setTimeout`s. They cannot fire into a later game, because a new game can only start from the action row, and the row appears only when the last of those timers fires. I left them as they were.
- The colour wheel's hover tooltip now sits further right (the row is wider). On phones its right edge is clipped by the card by a few px. It only shows on hover.
